# LuaDraw 曲面网格与相交场景的渲染选择

这份说明由 compare-figure 项目维护，是本项目的补充参考，不是 LuaDraw 官方手册或作者承诺。它总结已验证的 LuaDraw 3.7 曲面绘制经验，供 Agent 和绘图人员按场景选择渲染路线。它不是对所有曲面的通用修复，也不意味着所有图都应裁切曲面。实际本地案例验证了本文所述行为；下文给出可复用的 API 思路，不要求读者访问本地运行目录。

上游讨论中，LuaDraw 作者针对复杂非凸曲面指出 `Dscene3d` 面片拆分未必适合这类对象，并展示了解析裁切后手动排序的思路：[LuaDraw Discussion #353（作者回复）](https://github.com/pfradin/luadraw/discussions/353#discussioncomment-18944504)。选择绘制方法时应结合几何关系和图面语义，而非把单个案例外推为算法定论。

## 方法选择

- **单个曲面网格：先试 `Dfacet`。** 它将每个原始 facet 整体填充并描边，按 facet 中心深度排序，不走 `Dscene3d` 的 BSP 面/线切分。已验证的单 torus 场景中，特定局部的密集短线毛刺与斜缺口消失、网格更连续。共享边会被相邻 facet 重复描绘，后绘 facet 也可能盖住邻边的一部分；中心排序不保证任意凹形或相交场景的正确遮挡。
- **多个曲面需统一排序：可评估 `Dmixfacet`，但不要称为精确交线/隐藏面算法。** 它把多个对象的 facets 合并后按中心排序，能跨颜色统一排序，却仍是全局中心排序启发式。跨曲面的整 facet 覆盖可沿网格边形成台阶，长面互相遮挡或排序循环也没有普遍保证。
- **`Dscene3d` 用于确实需要 BSP 切分的简单场景。** 它会切分面片和网格线段，再按深度交错输出；复杂、密集的非凸网格可能产生大量微段，有限宽 TikZ 笔画与不透明填充组合后可能呈现毛刺、端帽或局部断缝。此现象不证明 BSP 的三维分类计算错误，也不表示所有图都会出现。
- **相交曲面且图意是实体并集外表面时，考虑先按真实曲面方程裁分，再整体排序。** 这避免让未裁切的完整 quad 决定交界轮廓。裁切会改变可见表面语义，不能默认用于展示两个完整、互相穿透的曲面。

## 曲面方程与裁切示例

以两只相交 torus 为例，设蓝色 torus 的轴为 z，主半径 `R`、管半径 `r`；绿色 torus 的轴为 y，主半径 `S`、管半径 `q`，中心沿 z 平移 `z0`。可用连续隐式函数：

```text
F_blue(x,y,z)  = (sqrt(x^2+y^2)-R)^2 + z^2 - r^2
F_green(x,y,z) = (sqrt(x^2+(z-z0)^2)-S)^2 + y^2 - q^2
```

零集是曲面；函数正负侧用于界定实体内外。实际调用要与库的约定及选定不等号方向一致。对曲面 A，按另一曲面的真实隐式函数裁切，保留返回的外侧 patch 并收存内部 patch：

```lua
local Aoutside, Ainside = ld.cutfacet2(A, otherEquation, ">")
```

`cutfacet2` 返回两个 facet 集合：裁切函数指定一侧的 facets 与另一侧的 facets。检查不等号方向和返回侧，再按目标图意决定绘制哪一侧；不要仅凭变量名假定符号语义。对于 opaque solid union 的外表面，通常保留各对象落在对方实体外侧的 patch，随后把各外侧 patch 一次交给 `Dmixfacet`，并为每组保留自己的颜色/网格选项：

```lua
local Aout, Ain = ld.cutfacet2(A, F_other, ">")
local Bout, Bin = ld.cutfacet2(B, F_this, ">")
-- 依实际符号约定确认 Aout/Bout 确为目标外侧后再绘制
G:Dmixfacet(Aout, optsA, Bout, optsB)
```

这里的 `Ain`、`Bin` 仍是有效的另一侧结果；将它们省略只适用于图意确为实体并集外表面时。切边只在原网格 facet 上做局部细分，仍是有限网格近似，不是精确曲面 Boolean。

## 工作流程

1. 写出每个曲面的连续隐式方程，并明确要表达的是完整相交曲面、实体并集外壳，还是仅某一对象的可见网格。
2. 从最简单且符合图意的渲染方式开始：孤立曲面先比较 `Dfacet` 与 `Dscene3d`；跨面遮挡可检查 `Dmixfacet`；仅当外壳语义明确时才尝试解析裁边。
3. 若裁切，逐对象用对方的真实方程分区，确认两侧返回值和正负号，再绘制所需 patch。不要用线性化图片边界或拟合网格代替实际方程。
4. 交线单独处理。可在参数域求隐式等值线、将数值采样点投回解析零集，并对每个线段作可见性筛选；有限 ray 采样可能漏掉窄掠过或很短的遮挡。仅把筛选后的可见线段按正确深度层次加入场景。
5. 检查整图中的构图、对象关系和颜色，再检查关键交界与网格的放大局部。不能只凭局部分数或某一块看似干净就认定整图正确。
6. 将观测限定在所测参数、网格和视角。用同几何、同尺寸的整图及局部对照区分改善来自何处；不把单例说成普遍修复。

## 重要限制

`cutfacet2` 基于 facet 边端点处隐式函数的符号变化寻找裁切交点，要求函数连续，并假定每条被检边至多一次过零。若端点同号而边内有双交点，可能漏切；稀疏网格、切触、极短边都需要额外验证。LuaDraw 3.7 的求根细节不应被当作适用于任意输入的健全终止或根数保证。

`Dmixfacet` 是全局 facet-center 排序，不是 BSP，也不是精确的多曲面可见性解算。红色交线若直接最后全覆盖，会压到前景面上，制造穿透错觉；可见性检测也不是万能，必须与表面深度/图层策略一起检查。不得以“最后重画全部网格边”作为修复：背面线条会被一并显示。

## 实测范围

本地已对原 torus 几何、网格 `49×33` 与 `49×21` 做了同条件实验，保持视角及页面设置不变。单曲面 Dfacet 在被检查区域改善了 Dscene3d 的短碎线观感；双曲面 Dmixfacet 单独使用仍在交界处显示整 facet 阶梯。按真实隐式方程裁切外侧 patch 后再全局排序，在该相交环面例中改善了交界与网格连续性；有限采样红线也只绘制筛选后的可见段。这里是特定场景的实测结果，不是 LuaDraw 的普遍修复保证、精确 Boolean 证明或对任意曲面的遮挡正确性证明。
